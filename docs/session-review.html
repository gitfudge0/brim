00The thesis

brim didn't lack features — it lacked reach. So the session fixed the distribution and contribution layer, not the product.

What drives stars

Frictionless install, green CI badges, works on every OS, an obvious "how to contribute" path.

What we left alone

The core (provider trait, confidence model, SQLite history) is already clean and well-tested. Don't touch what works.

01CI/CD — the trust signal

.github/workflows/ci.yml

fmt --check + clippy -D warnings on Linux, plus cargo test across Linux · macOS · Windows matrix.

.github/workflows/release.yml

Tag v* → cross-compile 4 targets → upload tarballs/zip + SHA256 to the GitHub release.

  • Targets: x86_64-linux, aarch64-darwin, x86_64-darwin, x86_64-windows-msvc
  • Plus dependabot.yml for weekly Cargo + Actions bumps

02Frictionless install

Before: clone + cargo build. After: one line, no toolchain.

  • cargo binstall brim-cli — grabs a prebuilt binary via release-asset metadata in crates/cli/Cargo.toml
  • Prebuilt binary downloads from the Releases page — Linux, macOS (Apple Silicon + Intel), Windows
  • README install section rewritten — binstall / prebuilt / from-source, in that order
  • Added repository + homepage + description for crates.io readiness

03Windows support (was Linux/macOS only)

schtasks autosync module

New cfg(windows) arm in service.rs registers a Task Scheduler job (/sc onlogon, scoped to the user via /ru).

The real blocker: keyring

keyring was pinned to linux-native for all platforms — macOS/Windows builds would never have linked.

  • Now per-target: linux-native / apple-native / windows-native + a no-backend fallback
  • Caveat: macOS/Windows compiles are verified by CI — no cross-toolchain on this Linux box

06Pre-existing fixes (so new CI is green)

The new gates would have failed on day one against existing code. Fixed first:

  • rustfmt violations in brand.rs and commands/mod.rs — cosmetic, auto-formatted
  • clippy ptr_arg in core/history.rs — &mut Vec<f64> → &mut [f64]

Result: a clean baseline that the CI I added actually passes.

08Deliberately NOT built

Honesty over checkbox-completion. Each of these is a real recommendation, but wrong to build blind this session:

New providers · $ cost tracking

Need real provider API credentials to test. Untested integration is worse than none. Guide written instead.

Dynamic plugin system

YAGNI — the Provider trait already extends to N providers in one binary. Dynamic loading is speculative.

1.0 version bump

A stability promise is the owner's call, not an agent's.

Budget threshold alerts

Feasible on existing % data, but needs a cross-platform notification dep + testing. Flagged as next.
